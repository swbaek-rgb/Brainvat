# 뇌 3D화 + 픽셀 셰이딩 계획 (2026-10-14)

목표: 통 안의 뇌를 3D 모델로 바꾸고, 지금의 4색 디더링 픽셀 룩을 유지한 채
기포·흔들림을 입체로 보여주며, 마우스 드래그로 돌려볼 수 있게 한다.

## 0. 범위 결정 (먼저)
- 3D로 가는 것: 뇌(+액체 안 기포)만. 유리통·뚜껑·관은 2D 스프라이트 유지.
- 3D 캔버스는 지금 통 스프라이트의 유리 영역(약 150×120 @1x) 위에 겹친다.
- 그려야 할 캔버스는 통 1개당 1장. 3개면 3개 WebGL 컨텍스트 → 가벼워야 함.

## 1. 모델 뽑기 (Astra)
- 입력: 지금 통 스프라이트의 뇌 부분이 아니라, 선명한 참고 이미지를 새로 뽑아 넣는다.
  "a human brain, front three-quarter view, plain gray, soft studio light, black background, no stem"
  픽셀 이미지는 3D 변환에 안 맞는다. 사실적인 회색 뇌 1장이 가장 잘 된다.
- 출력: GLB (없으면 OBJ+MTL). 텍스처는 쓰지 않을 것이므로 없어도 됨.
- 확인: 3면(정면/측면/위)에서 뇌 주름 깊이가 살아 있는지. 주름이 평평하면 셰이딩 때 그냥 공이 됨.
- 정리: Blender에서 (a) 삼각형 3,000~8,000개로 Decimate, (b) 원점을 중심으로, (c) 크기 1 단위,
  (d) 정면이 -Z 또는 +Z 한쪽으로 통일, (e) GLB로 재내보내기. 파일은 prototype/models/brain.glb.

## 2. 뷰어 뼈대 (Three.js)
- prototype/brain3d.html: 독립 테스트 페이지. 검정 배경, 뇌 1개, OrbitControls(드래그 회전, 줌/팬 끔).
- 조명은 2개로 고정: 위에서 오는 주광 1, 뒤에서 오는 역광 1. 픽셀 셰이딩은 조명 수가 적어야 단계가 깨끗함.
- 뇌 재질은 색 없음(흰색 Lambert). 색은 3단계에서 입힌다.

## 3. 픽셀 셰이딩 (룩의 핵심)
- 저해상도 렌더 타깃: 뇌 영역을 96×80 정도로 렌더하고 캔버스에 nearest로 확대. 이것만으로 픽셀 룩 절반.
- 후처리 셰이더 1개로 끝낸다:
  (a) 밝기를 4단계로 양자화 → 통 스프라이트의 4색(검정/어두운 갈색/분홍회색/뼈색)에 매핑
  (b) 4×4 Bayer 행렬로 디더 → 스프라이트의 점 패턴과 같은 질감
  (c) 외곽선: 깊이 차이가 큰 픽셀은 검정 → 뇌 윤곽이 스프라이트처럼 또렷
- 확인 기준: 정지 화면을 캡처해서 2D 통 스프라이트 옆에 두었을 때 "같은 그림체"로 읽히는지.
  색이 5개 이상 보이거나 그라데이션이 보이면 실패.

## 4. 애니메이션
- 뇌 떠다님: y축 sin 진동(진폭 1~2픽셀, 주기 3초) + 아주 느린 y축 회전(1분에 1바퀴). 드래그 중엔 회전 멈춤.
- 기포: 뇌 아래에서 위로 오르는 작은 구(또는 빌보드) 20개 파티클. 뇌 뒤/앞으로 섞여 지나가면 입체감 생김.
  기포도 같은 후처리를 통과하므로 자동으로 4색.
- 상태 연동(기존 FX 큐 재사용):
  grant → 기포 폭발 + 주광 밝기 2배(빛기둥 대신), deny → 주광 0.5초 어둡게,
  bad/cost → 뇌 흔들림(x축 노이즈) + 기포 정지, death → 회전·기포 멈추고 조명 서서히 꺼짐, tap → 뇌 1프레임 위로 튐.
- 액체 탁해짐: 신앙이 낮으면 후처리에서 "뼈색" 단계를 "분홍회색"으로 내려 전체가 어두워지게.

## 5. 통 화면에 합치기
- vats.html의 .tank 위에 <canvas class="brain3d"> 겹침. 유리 영역만 보이도록 CSS 마스크(스프라이트에서 유리 부분 알파 마스크 1장 추출).
- 2D 스프라이트에서 뇌 픽셀은 지워야 겹치지 않음 → tank_empty.png 계열을 바탕으로 쓰고 기포는 3D 쪽이 담당.
- 통 3개 = Three.js 렌더러 3개. 느리면 렌더러 1개로 3개 씬을 순서대로 그리고 각 캔버스에 복사.
- 드래그: tankwrap의 클릭(두드리기)과 충돌. 드래그 거리 < 4px이면 클릭(tap), 아니면 회전으로 구분.
- 모바일/저사양 대비: WebGL 실패 시 지금의 2D 스프라이트로 자동 복귀.

## 6. 다듬기
- 뇌 모델의 4색 분포가 스프라이트와 맞도록 조명 각도·양자화 문턱값 튜닝.
- 드래그 뒤 2초 지나면 정면으로 천천히 복귀(선택).
- 성능 목표: 3통 동시에 60fps, 안 되면 30fps 고정.

## 순서 요약
1 모델 → 2 뷰어 → 3 픽셀 셰이딩 → 4 애니메이션 → 5 합치기 → 6 다듬기
3단계까지 끝난 캡처를 보고 "같은 그림체"가 아니면 4 이후로 가지 말 것.
